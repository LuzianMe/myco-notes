# Myco Notes kit: contributor guide (for people and agents changing this repository)

This repository is a kit, not a notes repository. Do not confuse it with the notes repositories it creates (those start from `skills/myco-notes/template/`).

## Layout
- `skills/myco-notes/` : the whole product, **self-contained** (a skill-only installer delivers just this folder). `SKILL.md` (kept short: it routes each request to one file in `modes/`, the steps of that mode), `tools/`, `docs/` (the framework: `METHODOLOGY.md` and `FORMAT.md`; everything else is its reference implementation), `template/`. Nothing in it may refer to files outside the folder or to an environment variable.
- `.claude-plugin/` : Claude Code plugin and marketplace manifests (the plugin root is the repository root); Codex reads the same marketplace file.
- `.codex-plugin/plugin.json` : Codex plugin manifest (display name, icon, prompts); its `version` moves with the others.
- `tests/` : `smoke.sh` and `native.py` test the tools; run both before every commit, all checks must pass. `tests/behaviour/run.py` tests what an agent following the skill does: without arguments it checks each scenario's reference actions and that a typical mistake is caught (CI runs this); with `--agent CMD` it says each scenario to a real agent. Run it with a real agent after changing `SKILL.md`, a mode file or `template/AGENTS.md`. `tests/browser.py` opens the mycelium view in Chromium (Playwright, a test-only dependency; it skips without it): run it after changing `graph-template.html` or `notes_graph.py`. `.github/workflows/test.yml` runs all of them, plus pyflakes, for every push and pull request.
- `scripts/release.py` : moves the version in all four places (rule 4) and checks a release; `.github/workflows/release.yml` tags and releases a new version when it reaches main.
- `examples/` : sample entries for readers; `examples/demo/build_demo.py` builds the made-up demo notes behind the README screenshots and the live demo (`.github/workflows/demo.yml` publishes its map on GitHub Pages). Images for the README live in `.github/assets/`.

## Rules
1. **One copy of everything.** Do not duplicate tools or docs for a second agent; add installation instructions instead.
2. **Stay agent-neutral** in `SKILL.md`, `tools/` and `template/`. Agent-specific text belongs in the README or in the manifest folders.
3. **No secrets, no personal data** (hostnames, paths, addresses) in any file or commit; the tests use obviously fake values.
4. **Versions move together:** `.claude-plugin/plugin.json` `version` equals `.codex-plugin/plugin.json` `version`, `metadata.version` in `SKILL.md` and `VERSION` in `skills/myco-notes/tools/_myco.py` (the test checks it). Bump all four with `python3 scripts/release.py X.Y.Z`, add the `## X.Y.Z` section to `CHANGELOG.md` (`scripts/release.py --check` tells you what is missing); when it is merged into main, `.github/workflows/release.yml` tags `vX.Y.Z` and makes the GitHub release from that section.
5. `SKILL.md` follows the Agent Skills specification (name equals the folder name, description at most 1024 characters, under 500 lines) and stays short (under 12 KB, the test checks it): it is loaded whole every time the skill triggers. It routes each request to one file in `modes/`; the steps of a mode belong in its mode file.
6a. **No content-rewriting attributes in the kit:** the kit's `.gitattributes` is `* -text` (the plugin directory refuses `eol`, `text`, `filter` and `export-*` rules). Commit `.cmd` launchers with CRLF and everything else with LF; new notes repositories get their normalising rules from `template/gitattributes`, which `bootstrap` installs as `.gitattributes`.
6. Tools are Python 3.8+ (standard library only) and git, with an extension-less `sh` launcher and a `.cmd` launcher for each. Keep them working on Linux, macOS and Windows (CI runs `tests/smoke.sh` on Linux and macOS and `tests/native.py` on all three). Do not add GNU-only shell commands or new dependencies.
8. **Never hard-code folder names** (`notes/`, `tools/`, `docs/`, `notes-map/`) in a tool: read them with `_myco.layout(root)`, which follows `.myco-notes.conf` (new repositories: everything under `myco-notes/`; repositories without `MYCO_DIR`: the older flat layout, which must keep working). Template files use the `{{NOTES_DIR}}`, `{{TOOLS_DIR}}`, `{{DOCS_DIR}}`, `{{MAP_DIR}}` placeholders. Tests cover both layouts and `relocate`.
7. Change the framework first: the method in `docs/METHODOLOGY.md`, and `docs/FORMAT.md` when what is on disk changes (bump `FORMAT_VERSION` in `_myco.py` per its section 10). Then the tools and template that implement it (method section 17 maps one to the other).
